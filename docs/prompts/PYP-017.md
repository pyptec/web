# PYP-017 — Actualización controlada de Vite

Proyecto: D:\promate\web\pyp-web

## OBJETIVO

Actualizar Vite de la versión 6.4.1 a la versión 6.4.4, siempre que se confirme que es compatible y que corrige las vulnerabilidades identificadas en PYP-015.

Preservar el funcionamiento de la web, la generación SEO, el formulario Netlify y la documentación VitePress.

## FASE 1 — AUDITORÍA

1. Leer AGENTS.md.
2. Revisar los informes PYP-015 y PYP-016.
3. Ejecutar git status --short.
4. Verificar versiones actuales de Vite, Node y npm.
5. Revisar package.json y package-lock.json.
6. Ejecutar npm audit y npm ls vite.
7. Identificar las versiones de Vite instaladas, incluida la utilizada por VitePress.

Confirmar que Vite 6.4.4 existe, es compatible y corrige las vulnerabilidades objetivo.

No continuar si no se cumplen estas condiciones.

## FASE 2 — ACTUALIZACIÓN

Actualizar exclusivamente la dependencia directa Vite a 6.4.4.

Permitir únicamente cambios transitivos necesarios.

No actualizar deliberadamente:

- React.
- React Router.
- Tailwind.
- VitePress.
- Otras dependencias independientes.

No utilizar npm audit fix ni npm audit fix --force.

No modificar código comercial salvo que sea estrictamente necesario para mantener compatibilidad.

## FASE 3 — VALIDACIÓN

Ejecutar:

1. Compilación comercial en directorio temporal.
2. Generación SEO.
3. Verificación de las cuatro rutas.
4. Validación de navegación corporativa y local.
5. Verificación del formulario Netlify.
6. Comprobación de sitemap y metadatos.
7. Compilación VitePress.
8. Pruebas en escritorio y móvil, cuando estén disponibles.
9. npm audit.
10. npm audit --omit=dev.
11. npm ls vite.
12. git diff --check sobre archivos modificados.

Comparar los resultados con PYP-016.

Confirmar que los 17 archivos existentes de dist conservan sus hashes.

## RESTRICCIONES

No realizar actualizaciones masivas.

No modificar dist ni otros archivos generados existentes.

No realizar envíos reales del formulario.

No ejecutar git add, commit, push, reset, clean ni despliegue.

Si la actualización requiere cambios mayores o provoca regresiones, detenerse y documentar el problema antes de continuar.
