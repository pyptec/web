# PYP-020 — Commit y push de cierre de jornada

Proyecto: D:\promate\web\pyp-web

## OBJETIVO

Realizar el commit y push de los cambios acumulados y validados de PYP Tecnología Electrónica SAS, utilizando la selección revisada en PYP-019.

El usuario autoriza expresamente el staging, commit y push a GitHub para cerrar la jornada.

No autoriza despliegues de Netlify ni modificaciones funcionales adicionales.

## FASE 1 — VERIFICACIÓN PREVIA

1. Leer AGENTS.md y respetar sus restricciones, considerando la autorización explícita de commit y push de esta intervención.
2. Leer docs/evidencias/PYP-019/resultado.md.
3. Leer docs/evidencias/PYP-019/seleccion-commit.txt.
4. Ejecutar:
   - git status --short
   - git branch --show-current
   - git remote -v
   - git fetch origin
   - git status -sb
5. Confirmar que la rama es main y el remoto corresponde a [https://github.com/pyptec/web.git](https://github.com/pyptec/web.git).
6. Comprobar que main local no esté por detrás de origin/main ni haya divergencia.

Si existen commits remotos nuevos, detenerse y solicitar revisión. No ejecutar pull, merge, rebase ni force push automáticamente.

## FASE 2 — PREPARACIÓN DEL STAGING

Utilizar exclusivamente el manifiesto aprobado de PYP-019:

git --literal-pathspecs add --pathspec-from-file=docs/evidencias/PYP-019/seleccion-commit.txt

Verificar que el propio manifiesto, la bitácora y los documentos PYP-020 necesarios queden incluidos.

Retirar únicamente del índice Git estos tres archivos generados, conservándolos en disco:

git rm --cached -- dist/index.html dist/assets/clg-DhiTCHTU.jpeg dist/assets/rpi-DDLAJPsT.jpg

No ejecutar git clean ni eliminar archivos físicos.

## FASE 3 — REVISIÓN DEL STAGING

Ejecutar:

- git diff --cached --name-status
- git diff --cached --stat
- git diff --cached --check
- git status --short

Verificar:

1. Que todos los archivos staged correspondan al manifiesto o a las tres bajas autorizadas de dist.
2. Que no existan secretos, archivos .env, perfiles, cachés ni builds temporales.
3. Que las fuentes y recursos necesarios estén incluidos.
4. Que los tres archivos de dist sigan existiendo físicamente.
5. Que no haya modificaciones inesperadas fuera del staging.

Si hay diferencias relevantes, detenerse antes del commit.

## FASE 4 — COMMIT

Si las verificaciones son correctas, ejecutar:

git commit -m "feat: integrar navegación, SEO y documentación PYP"

Registrar el hash del commit.

No crear commits adicionales salvo autorización.

## FASE 5 — PUSH

Confirmar nuevamente que el remoto no avanzó desde la verificación previa.

Ejecutar:

git push origin main

No utilizar --force.

Si el push es rechazado, detenerse y reportar el motivo. No reescribir historial.

## FASE 6 — VERIFICACIÓN FINAL

Ejecutar:

- git status -sb
- git log -1 --oneline
- git rev-parse HEAD
- git ls-files dist

Confirmar que:

1. El commit existe.
2. El push fue aceptado.
3. main local coincide con origin/main.
4. No hay cambios pendientes inesperados.
5. Los tres archivos de dist ya no están versionados.
6. Los archivos locales de dist permanecen intactos.

## DOCUMENTACIÓN

Antes del commit, guardar este prompt completo en:

docs/prompts/PYP-020.md

Actualizar la bitácora y el índice de prompts.

Registrar la autorización del usuario para commit y push.

Después del push, entregar el hash real del commit y el resultado de la operación.

No modificar archivos versionados después del commit únicamente para registrar el resultado, salvo autorización posterior. El resultado final puede quedar en el informe de Codex para incorporarlo a la bitácora mañana.

## RESTRICCIONES

No modificar código funcional.

No actualizar dependencias.

No ejecutar git reset, git clean ni force push.

No desplegar manualmente en Netlify.

No realizar envíos reales del formulario.

Si GitHub está conectado a Netlify mediante despliegue automático, advertir que el push puede activar una publicación sin intervención manual. No asumir que esa integración está desactivada.

Entregar:

A. Número de archivos incluidos.

B. Archivos retirados del índice.

C. Hash del commit.

D. Resultado del push.

E. Estado final de Git.

F. Advertencia sobre posible despliegue automático de Netlify.

G. Pendientes para mañana.
