# PYP-027 — Publicación controlada de CLG en producción

Proyecto: D:\promate\web\pyp-web

Repositorio: [https://github.com/pyptec/web](https://github.com/pyptec/web)

Sitio: [https://pyptecnologia.com](https://pyptecnologia.com)

Nueva página aprobada: /proyectos/clg/

## OBJETIVO

Preparar, publicar y verificar en producción la página comercial CLG, correspondiente a las tareas PYP-025 y PYP-026.

El propietario ha aprobado visualmente la implementación.

La publicación debe preservar las cuatro páginas anteriores, el formulario de contacto, el SEO existente y todos los archivos locales ajenos a la tarea.

## FASE 1 — AUDITORÍA PREVIA

Antes de modificar o publicar:

1. Leer AGENTS.md.
2. Revisar los informes PYP-025 y PYP-026.
3. Ejecutar git status --short.
4. Revisar git diff y archivos no rastreados.
5. Identificar exactamente los cambios de CLG.
6. Separar cambios aprobados de archivos ajenos a la tarea.
7. Confirmar que no hay credenciales ni información sensible.
8. Verificar que las imágenes de CLG están incorporadas.
9. Confirmar que no se han alterado los 17 archivos locales de dist.

No ejecutar git add . indiscriminadamente.

## FASE 2 — VALIDACIÓN FINAL

Comprobar:

- Las cinco rutas del sitio.
- La página /proyectos/clg/.
- Infografía principal y enlace de ampliación.
- Fotografías reales de CLG.
- Galería técnica.
- Diseño móvil.
- Navegación y enlaces.
- Formulario existente.
- Título, description y canonical.
- Open Graph.
- JSON-LD.
- Sitemap.
- robots.txt.
- HTML inicial de CLG.
- Ausencia de errores de compilación.
- Ausencia de vulnerabilidades de producción.

Ejecutar las pruebas disponibles y registrar los resultados.

No modificar dependencias.

No ejecutar npm audit fix.

## FASE 3 — PREPARAR PUBLICACIÓN

Generar un manifiesto de archivos que deben entrar al commit.

Incluir únicamente:

- Implementación CLG.
- Ajustes visuales aprobados.
- Recursos gráficos necesarios.
- Cambios SEO relacionados.
- Documentación PYP-025, PYP-026 y PYP-027.

Excluir:

- Archivos temporales.
- Cachés.
- Credenciales.
- Archivos de desarrollo ajenos.
- Los 17 archivos locales de dist.

Mostrar el manifiesto y comprobar que no se incorporan archivos inesperados.

## FASE 4 — COMMIT Y PUSH

Una vez completadas satisfactoriamente las verificaciones:

1. Realizar staging selectivo.
2. Verificar git diff --cached.
3. Crear un commit con mensaje:

feat(clg): publicar página comercial y SEO de CLG

4. Registrar el SHA completo.
5. Ejecutar push hacia main, siempre que la rama local y remota estén en condiciones seguras para ello.

No utilizar force push.

No reescribir historial.

Si existe divergencia o un conflicto, detenerse y reportarlo.
