# PYP-010 — Organización del repositorio y control de archivos

Proyecto: D:\promate\web\pyp-web

## OBJETIVO

Preparar el repositorio Git para una publicación controlada, identificando archivos fuente, documentación, salidas generadas y archivos temporales.

Corregir únicamente las reglas de exclusión que puedan justificarse sin eliminar archivos ni perder cambios.

## FASE 1 — AUDITORÍA

1. Leer AGENTS.md.
2. Leer docs/evidencias/PYP-009/informe.md.
3. Leer docs/evidencias/PYP-009/propuesta-commit.md.
4. Ejecutar git status --short.
5. Inspeccionar .gitignore.
6. Ejecutar git ls-files dist.
7. Clasificar archivos sin seguimiento por directorio, extensión y finalidad.
8. Identificar los archivos de código necesarios para que la web funcione.

No modificar archivos durante esta fase.

## FASE 2 — CONTROL DE ARCHIVOS

Revisar y actualizar .gitignore solamente cuando sea necesario.

Excluir de futuros commits:

- node_modules.
- Cachés y perfiles temporales.
- Salidas generadas de VitePress.
- Resultados temporales de pruebas.
- Archivos de sistema y editores que no pertenezcan al proyecto.

No excluir código fuente, documentación oficial, prompts ni evidencias necesarias.

No modificar el contenido de dist.

Si dist contiene archivos ya versionados, documentar exactamente cuáles son y proponer cómo dejar de seguirlos sin borrarlos del disco. No ejecutar todavía esa operación.

## FASE 3 — DOCUMENTACIÓN

Guardar este prompt completo en:

docs/prompts/PYP-010.md

Actualizar:

- docs/BITACORA_DESARROLLO.md
- docs/prompts/index.md

Crear:

docs/evidencias/PYP-010/informe.md

El informe debe incluir:

- Estado inicial del repositorio.
- Clasificación de archivos.
- Cambios realizados en .gitignore.
- Archivos que deben versionarse.
- Archivos que deben excluirse.
- Archivos que requieren revisión humana.
- Comandos recomendados para una futura preparación de commit.

No inventar resultados.

## FASE 4 — VALIDACIÓN

1. Ejecutar git status --short.
2. Ejecutar git diff --check sobre los archivos modificados.
3. Verificar que los archivos fuente siguen visibles para Git.
4. Comprobar que las salidas generadas quedan excluidas correctamente.
5. Verificar que no se eliminaron archivos.
6. Confirmar que dist conserva su contenido.

No ejecutar git add, git rm, git clean, git reset, commit, push ni despliegue.

## INFORME FINAL

Entregar:

A. Archivos modificados.

B. Reglas de exclusión agregadas o corregidas.

C. Clasificación de los archivos sin seguimiento.

D. Archivos versionados dentro de dist.

E. Propuesta de preparación del commit.

F. Riesgos y pendientes.

G. Estado final de Git.

Registrar PYP-010 en la bitácora.

No realizar commit ni push.
