# PYP-015 — Auditoría y actualización controlada de dependencias

Proyecto: D:\promate\web\pyp-web

## OBJETIVO

Analizar las vulnerabilidades de npm identificadas en PYP-009 y determinar las actualizaciones seguras para PYP Tecnología Electrónica SAS.

Priorizar las dependencias utilizadas en producción, especialmente React Router.

No realizar actualizaciones automáticas ni cambios masivos.

## FASE 1 — DIAGNÓSTICO

1. Leer AGENTS.md.
2. Revisar docs/evidencias/PYP-009/informe.md.
3. Revisar las intervenciones PYP-010 a PYP-014.
4. Ejecutar git status --short.
5. Inspeccionar package.json y package-lock.json.
6. Ejecutar npm audit --json y npm audit --omit=dev --json.
7. Consultar npm ls para identificar versiones instaladas y dependencias transitivas.

Registrar las versiones reales y el estado inicial.

## FASE 2 — CLASIFICACIÓN

Para cada vulnerabilidad identificar:

- Paquete afectado.
- Versión instalada.
- Severidad.
- Dependencia directa o transitiva.
- Uso en producción o desarrollo.
- Versión que corrige la vulnerabilidad.
- Compatibilidad con el proyecto.
- Riesgo de regresión.

Distinguir las vulnerabilidades del código que se ejecuta en el navegador de las relacionadas únicamente con herramientas de desarrollo.

No interpretar automáticamente una alerta alta de desarrollo como una vulnerabilidad explotable en la web publicada.

## FASE 3 — PROPUESTA DE ACTUALIZACIÓN

Preparar un plan de actualización mínima.

Priorizar:

1. Dependencias de producción.
2. Correcciones compatibles sin cambios mayores.
3. Herramientas de desarrollo con vulnerabilidades relevantes.

Si una actualización requiere cambio mayor, explicar sus consecuencias y solicitar autorización antes de aplicarla.

No ejecutar npm audit fix ni npm audit fix --force.

No instalar ni actualizar paquetes en esta intervención.

## FASE 4 — PRUEBAS DE REFERENCIA

Sin alterar las dependencias existentes:

1. Ejecutar compilación comercial en directorio temporal.
2. Ejecutar compilación VitePress.
3. Verificar rutas y navegación.
4. Verificar formulario Netlify.
5. Verificar generación SEO.
6. Registrar cualquier error existente antes de actualizar.

Estas pruebas servirán como referencia para comparar futuras actualizaciones.

## RESTRICCIONES

No modificar package.json ni package-lock.json.

No instalar dependencias.

No ejecutar npm audit fix.

No modificar componentes React, SEO, formulario ni navegación.

No modificar dist.

No ejecutar git add, commit, push, reset, clean ni despliegue.

## INFORME FINAL

Entregar un diagnóstico y una propuesta concreta de actualización, indicando qué paquetes deben actualizarse, a qué versiones y por qué.

No aplicar actualizaciones sin autorización.
