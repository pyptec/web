# PYP-002 — Extraer Navbar compartido (primera integración)

## Contexto
Proyecto PYP Tecnología Electrónica SAS, React/Vite/Tailwind. Auditoría PYP-001 completada. La barra de `src/pages/AutomatizacionEdge.jsx` es la referencia visual aprobada.

## Objetivo
Crear `src/components/Navbar.jsx` reutilizable y usarlo **solo** en `src/pages/AutomatizacionEdge.jsx`, sin alterar el contenido de las páginas ni su comportamiento de navegación.

## Instrucciones para Codex
1. Antes de editar, ejecutar `git status --short` y `git diff -- src/pages/AutomatizacionEdge.jsx src/main.jsx src/components/Seo.jsx`. Reportar cambios preexistentes. No descartarlos ni sobrescribirlos.
2. Inspeccionar la implementación real del encabezado de Edge y sus imports. Confirmar la ruta real del logo `src/assets/proyectos/log_pyp.webp`.
3. Extraer ese encabezado a `src/components/Navbar.jsx`, manteniendo estructura visual, dimensiones, colores corporativos (`#A6CE39`, `#416D13`, `#6BA425`, `#1E1E1E`), logo, enlaces, anclas, comportamiento móvil actual y accesibilidad existente.
4. Diseñar props sencillas para reutilizar el componente posteriormente, pero **no añadir todavía** nuevos enlaces, dropdown ni menú hamburguesa. No modificar `App.jsx`, `MonitoreoEnergetico.jsx` ni `IoTIndustrialLoRaWAN.jsx`.
5. Sustituir solo el encabezado de `AutomatizacionEdge.jsx` por `<Navbar ... />`, conservando sus destinos locales (`#j1939`, etc.). Eliminar únicamente imports que hayan quedado sin uso.
6. No editar `main.jsx`, `Seo.jsx`, `index.css`, `index.html`, `package.json`, sitemap, archivos de Netlify ni `dist`.
7. Mostrar diff de los archivos editados y explicar los cambios. No ejecutar commit, push ni despliegue.

## Validación
- Verificar que Edge tenga exactamente una barra y que el logo lleve a `/`.
- Confirmar que todas las anclas de Edge sigan funcionando.
- Si es posible compilar sin tocar el `dist` existente, utilizar una salida temporal distinta, por ejemplo `npx vite build --outDir /tmp/pyp-navbar-build` (adaptar la ruta al sistema). Si no es seguro, explicar por qué y no ejecutar build.
- Revisar visualmente en escritorio y móvil solo si el entorno permite abrir el navegador. No declarar pruebas visuales realizadas sin evidencia.

## Entrega requerida
A. Archivos creados y modificados.
B. Diff resumido y justificación técnica.
C. Resultado de validaciones realizadas y pendientes.
D. Estado Git final y confirmación de que no se alteraron cambios previos.
E. Texto breve para registrar en bitácora PYP-002.

**Importante:** detenerse si se descubre un conflicto que pueda sobrescribir cambios existentes; solicitar revisión antes de continuar.
