# PYP-014 — Verificación de entrega SEO y compatibilidad con Netlify

Proyecto: D:\promate\web\pyp-web

## OBJETIVO

Verificar que las cuatro páginas de PYP entreguen sus metadatos SEO correctos desde el HTML inicial, tanto con barra final como sin ella, y que el resultado sea compatible con el despliegue de Netlify.

Resolver únicamente los problemas demostrados mediante pruebas.

## FASE 1 — AUDITORÍA

1. Leer AGENTS.md.
2. Leer docs/evidencias/PYP-013/resultado.md.
3. Revisar la bitácora y el estado Git.
4. Inspeccionar:
   - src/data/seo.js
   - src/components/Seo.jsx
   - scripts/generar-seo.mjs
   - index.html
   - public/\_redirects
   - package.json
   - configuración de Netlify disponible.
5. Identificar cómo se generan y entregan los archivos HTML de las cuatro rutas.

## FASE 2 — VERIFICACIÓN DE RUTAS

Comprobar las siguientes URL:

- /
- /monitoreo-energetico
- /monitoreo-energetico/
- /iot-industrial
- /iot-industrial/
- /automatizacion-edge
- /automatizacion-edge/

Para cada dirección verificar:

- Código HTTP.
- HTML inicial recibido.
- Title.
- Meta description.
- Canonical.
- Open Graph.
- Funcionamiento de React Router.
- Ausencia de páginas en blanco.

Comparar los resultados del servidor de desarrollo, vite preview y el artefacto generado.

No asumir que vite preview reproduce exactamente el comportamiento de Netlify.

## FASE 3 — COMPATIBILIDAD CON NETLIFY

Analizar la interacción entre:

- HTML generado por ruta.
- Regla SPA de \_redirects.
- Rutas con y sin barra final.
- Detección estática del formulario Netlify.

Determinar si es necesario ajustar el generador, la estructura de salida o las reglas de redirección.

Si no se dispone de un entorno Netlify real, indicar expresamente que la entrega en CDN no está verificada.

No modificar reglas sin demostrar la necesidad.

## FASE 4 — CORRECCIÓN CONTROLADA

Si se identifica un defecto reproducible:

1. Explicar su causa.
2. Aplicar la modificación mínima necesaria.
3. Mantener una única fuente de datos SEO.
4. Preservar las URL canónicas.
5. Conservar la navegación React Router.
6. Mantener el formulario Netlify.
7. Evitar nuevas dependencias.

Si no existe un defecto demostrado, no realizar cambios funcionales.

## FASE 5 — VALIDACIÓN

1. Compilación comercial en directorio temporal.
2. Generación SEO completa.
3. Comprobación del HTML inicial de cada ruta.
4. Verificación de canonical y Open Graph.
5. Verificación de sitemap y robots.txt.
6. Pruebas de rutas con y sin barra final.
7. Comprobación de detección estática del formulario.
8. Compilación VitePress.
9. git diff --check de archivos modificados.
10. Confirmación de que dist permanece intacto.
